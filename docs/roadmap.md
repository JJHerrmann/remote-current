# Roadmap

RemoteCurrent is a donation-supported public index of remote jobs. This file
records what it is trying to be and the order of work to get there. It sits
alongside [architecture.md](architecture.md) (how it is built) and
[source-discovery.md](source-discovery.md) (how coverage grows).

## Positioning

Do not compete on job count. Aggregators already hold millions of listings and
are unpleasant to use: stale reposts, ghost jobs, forced middleman application
flows. A larger pile of the same listings is not fundable.

Compete on **fresh, real, remote, and honest about provenance.** Every listing
is read directly from an employer feed, shows where it came from and when it was
first and last seen, links to the real application, and is never reordered for
payment. That is the product and the reason to donate to it.

A feature ships only if it serves that position.

## Funding model

Free forever, no gate. Support is voluntary through Ko-fi, with GitHub Sponsors
added for the open-source audience. Donations follow trust and habit, so the
roadmap front-loads retention (people come back) and transparency (the ask is
credible) ahead of raw coverage.

The ask is contextual, never a nag: a digest footer, or a prompt after repeated
"Apply direct" clicks, tied to a moment of received value. The site shows the
real monthly cost and how close it is to covered. No feature is ever donor-only.

## Phases

### Phase 1 — Retention primitives (in progress, September 2026)

- **Saved-search permalinks.** Filter state already lives in the URL; make it
  visible with a copy-link control on the board.
- **RSS feeds.** Static feeds generated by the crawler each run: everything,
  worldwide only, listings with pay, per source, per employer, plus a
  `feeds/index.json` catalog. Arbitrary-query RSS waits for the read API in the
  architecture doc's deployment target.
- `<link rel="alternate">` discovery and a "best matching feed" link that
  follows the active filters.

### Phase 2 — Trust surface (in progress, September 2026)

- **`sources.html`** — done. Feed health plus a per-source table (fetch count,
  remote yield, classifier confidence, scope mix, last OK, error). `/status`
  folded into its header banner rather than a separate page. Reads
  `data/sources.json`, written by `write_sources` each run.
- **`about.html`** — done. Who runs it (Orpheus Rook / rook.works), the pledge,
  the cost stance (free tiers today; paid infra shown transparently and only
  when support covers it), the Ko-fi ask (one-time or monthly).
- **Corrections** — done. `data/overrides.json` holds versioned drops and scope
  fixes applied by `apply_overrides`; each row on the board has a "flag" link
  that opens a pre-filled GitHub issue.
- Still open: surface the funding state on `about.html` once there is a real
  monthly cost to show.

### Phase 3 — Coverage multiplier (in progress, September 2026)

- **Discovery loop** — done. `crawler/discover.py` harvests ATS slugs from
  urlscan / Wayback CDX, validates against the live endpoint, and merges new
  Greenhouse / Lever / Ashby boards into the registry.
  `.github/workflows/discover.yml` runs it weekly. A dry run over Lever alone
  surfaced ~11 live boards not previously indexed.
- **`jsonld` adapter** — done. Standards-based fallback that parses
  server-rendered schema.org `JobPosting` markup from any careers URL.
- **Curated remote-first / notable tier** — done, first batch: +22 employers
  (Elastic, Twilio, Reddit, Mozilla, Scale AI, Grafana, Remote, ClickHouse,
  1Password, Docker, Sentry, Zapier, Webflow, and more), all resolving through
  existing adapters.
- **Workable / Teamtailor** — dropped. Workable's public widget API now returns
  empty job lists; Teamtailor's API needs auth. See source-discovery.md.
- Still open: a SuccessFactors adapter (McDonald's), a sitemap crawl feeding
  `jsonld` for SPA careers pages (Yum! Brands), and running the discovery loop
  at full width once it has an urlscan API key.

### Phase 4 — Distribution

- **Search discoverability** — done. Deploy-time prerender bakes the newest
  ~40 listings + `ItemList` / `Organization` / `WebSite` JSON-LD into
  `index.html`; `robots.txt`, `sitemap.xml`, Open Graph and Twitter cards with
  a rendered share image are in place. `crawler/seo.py`. Full effect needs a
  custom domain (root `robots.txt`) and a Search Console sitemap submission.
- **`story.html`** — done. The canonical "why it exists" essay, with `Article`
  / `BreadcrumbList` / `FAQPage` JSON-LD, its own OG tags, and a commented
  GoatCounter hook on every page pending an account. It is the pillar the
  launch kit and any future company pages link back to.
- Weekly email digest per saved search, plus a public weekly newsletter
  ("N new remote roles, M newly hiring distributed companies"). The newsletter
  is shareable content and the primary channel for the funding ask.
- Company pages — every current remote role at an employer, with history. An
  SEO surface and a reason to bookmark; also a place to emit per-employer
  JSON-LD.

### Phase 5 — Differentiation

- Ghost-job and repost flagging — listings open 60+ days, or gone and returned.
- Timezone-overlap filter — for remote work this matters more than country.
- Salary as a first-class filter with a visible coverage statistic.

## Not doing

- RTO giants (Apple, Meta, Google) chased at the cost of adapter effort. Near
  zero remote yield and active anti-scraping; a stub plus "not covered, and
  why" is the honest answer.
- Accounts, resume storage, in-product applications, mass apply.
- Any paid placement or ranking, at any time.
- Donor-only features.

## Open questions

- Read API host: a Cloudflare Worker (architecture doc) versus staying fully
  static with pre-generated artifacts. Static holds through Phase 1; Phase 4
  digests need a scheduled sender.
- Email provider and deliverability handling before Phase 4.
- Classifier accuracy measurement needs a labelled sample.
